### Requirement: Snapshot candidacy audit covers every apps/client component directory

Every directory of `apps/client` that may contain UI components SHALL be classified in the coverage matrix below (excluding `node_modules/`, `dist/` and `coverage/`). Each classified directory is either covered by phases F0-F3 (candidate) or excluded with an explicit reason; no directory may be silently omitted. Counts follow the **audit-time convention**: a directory keeps the file count of the original audit even when a dead file was later deleted (the 3 empty `providerOrder` files removed in `ed0af3bf`); the Datatable row already set this precedent.

#### Scenario: A directory outside the matrix must be classified first

- **WHEN** a new directory containing UI components appears under `apps/client` (a new module, a new `src/components/*` folder, or a new non-`src` directory)
- **THEN** it is added to the matrix and classified (candidate for F1-F3 or excluded with an explicit reason) before any snapshot test for it is merged

#### Scenario: Candidate totals stay reconciled across artifacts

- **WHEN** the candidate counts are read from `proposal.md`, `design.md`, this spec and `tasks.md`
- **THEN** all four agree on F1 = 37, F2 = 20, F3 = 26, 4 gap candidates (MenuBar, AttendeeList, EventCalendar, NotesFilters), total = 87 candidate files, and on 180 audited / 93 excluded

### Requirement: Container and dynamic surfaces are excluded from snapshot testing

Snapshot matchers SHALL NOT be used on `pages/*` containers, `App.jsx`/`main.jsx`, `*Dialog.jsx` or `*FiltersForm.jsx` components backed by react-hook-form/zod (sole exception: `modules/events/components/EventFiltersForm.jsx`, which has no RHF and is snapshotted subtree-only; `modules/notes/components/NotesViewDialog.jsx` also has no RHF but stays excluded because its render embeds a live `TiptapEditor` plus 2 RTK queries), interactive forms with validation state regardless of library (sole example: `modules/settingsProductCategories/components/SettingsProductsCategoryForm.jsx`, verified non-RHF yet still excluded as an interactive form with validation state), route guards, tiptap editors whose render depends on a live tiptap `Editor` instance (`TiptapEditor`; `MenuBar` is NOT in this list anymore: its render is driven by an `editor` prop and it SHALL be snapshotted through a flat prop stub, never through a `vi.mock` of `@tiptap/*`), components whose rendered markup is derived from Redux store state (a component that only _dispatches_ from Redux while rendering from props - e.g. `SideBar` - is a candidate, not excluded), providers, or any component whose rendered content depends on `Date.now()`, `new Date()`, `toLocaleString()`, `Math.random()` or `uuid` without being frozen or normalized first. Because `vi.setSystemTime` freezes `new Date()` and locale normalization fixes ICU-dependent output (e.g. `toLocaleDateString`), size and review-value - never determinism - are the only valid grounds for the remaining exclusions; conversely, a component excluded on size whose reviewed subtree is deterministic and under ~100 lines SHALL be reclassified as a candidate and snapshotted subtree-only (`AttendeeList` -> its `table`, `EventCalendar` -> the month grid, `NotesFilters` -> one matcher per block with the hashtag `Popover` closed). A render-only prop stub that cannot support interaction SHALL NOT be widened with `userEvent` just to add interaction assertions: those surfaces stay with explicit RTL assertions (`getByRole`, `getByText`, `userEvent`), and MenuBar additionally stays render-only until its stub is deliberately extended.

#### Scenario: A form dialog is covered by assertions, not snapshots

- **WHEN** a reviewer encounters a snapshot assertion added inside a `*Dialog.jsx` or `*FiltersForm.jsx` test
- **THEN** the change is rejected in favor of explicit role/text assertions, because input ids, validation messages and touched/dirty state are unstable across refactors

#### Scenario: An unfrozen date in a snapshot is rejected

- **WHEN** a snapshot test renders live `Date.now()`/`toLocaleString()` output without fake timers or normalization
- **THEN** it is treated as a defect: the test must freeze or normalize the value before the snapshot can be committed

#### Scenario: MenuBar is snapshotted through a flat prop stub, not a library mock

- **WHEN** a snapshot test is written for `components/tiptap/MenuBar.jsx` (333 lines, `({editor})` prop-driven)
- **THEN** it renders the component with a flat stub of the `editor` prop (`isActive: () => false`, `can: () => false`, `chain: () => ({ focus: vi.fn().mockReturnThis(), run: vi.fn() })`, `getAttributes: () => ({ href: '' })`) and performs NO `vi.mock` of `@tiptap/*`
- **AND** the test stays render-only: it does not use `userEvent` (a click against the minimal stub throws `TypeError`), and coexists with the existing RTL test for the component

#### Scenario: A size-excluded component with a deterministic subtree becomes a candidate

- **WHEN** a component previously excluded on size/review-value exposes a deterministic subtree under ~100 lines
- **THEN** it is reclassified as a gap candidate and snapshotted subtree-only: `AttendeeList` via `container.querySelector('table')` with RTK mocked from `../api/eventsAPI` and `Date.prototype.toLocaleDateString` normalized (locale ICU es-ES vs en-US), `EventCalendar` via the month grid only with the hardcoded `es` date-fns locale (L16/480) and `vi.setSystemTime` for its real `new Date()` calls (L200/430/442), `NotesFilters` via one matcher per block with `useGetHashtagItems`/`useGetNoteColumns` mocked from `../hooks/index` and the hashtags `Popover` closed
- **AND** the test file lives inside the component's `components/` directory (`src/modules/events/components/`, `src/modules/home/components/`, `src/modules/notes/components/`) so the relative `vi.mock` specifiers resolve identically to the component's own imports
